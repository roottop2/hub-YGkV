# 电商智能问答系统 —— 技术路线与设计文档

> 版本：v1.0　|　日期：2026-08-13
> 说明：本文档既是《技术路线》交付文档，也是本项目开发的**设计蓝本**。设计采用"可运行演示版 + 生产方案写透"的路线：代码交付一套能在 CPU 上跑通全流程的演示系统，同时文档给出扩展到生产规模（如 F1=91.26%、节点 31680、关系 82564 条）的完整方案。

---

## 一、项目概述

### 1.1 背景

电商平台每天面临海量用户咨询，典型问题分三类：

| 类别 | 示例问题 |
|---|---|
| 商品参数 | "这款手机支持 5G 吗？""耐克 Air Max 多少钱？" |
| 订单状态 | "我的订单到哪了？""订单 202608130001 发货了吗？" |
| 退换货政策 | "7 天无理由退货怎么算？""运费谁出？" |

两个核心痛点：
1. **人工客服**：响应慢、成本高、无法 24 小时在线；
2. **通用大模型**：缺少电商领域知识，容易"幻觉"——一本正经地编造错误答案。

### 1.2 目标

构建一个**基于知识图谱（Knowledge Graph）的电商智能问答系统**：
- 用户用自然语言提问；
- 系统先做**意图识别 + 实体抽取**，再通过 **BM25 检索 + 图检索**从知识图谱中找出**真实、准确的知识**；
- 最后用 **Deepseek 大模型**基于"检索内容 + 问题"生成自然流畅的回答。

通过 RAG（Retrieval-Augmented Generation，检索增强生成）把"检索到的真实知识"和"大模型的生成能力"结合，既准确又自然，同时规避幻觉。

### 1.3 关键技术点（来自需求）

- **RAG**：检索增强生成，本项目的主干思想；
- **BM25**：经典文本相关性打分算法，用于知识检索排序；
- **Neo4j**：图数据库（生产方案），本演示用**抽象存储层 + 内存图**实现；
- **CRF（条件随机场）**：序列标注解码，用于命名实体识别；
- **R-BERT**：带实体标记的 BERT 关系抽取模型；
- **BiLSTM**：双向长短期记忆网络，与 CRF 组成 NER 主干网络。

### 1.4 成果指标（生产目标）

- 命名实体识别 F1 达到 **91.26%**；
- 知识图谱规模：节点 **31680** 个，关系 **82564** 条；
- 1000 条测试集人工评测，回复满意度 **93%**。

> 说明：以上为原生产项目指标。本演示版在 CPU + 模拟数据条件下无法复现该规模，但会提供**同一套评测脚本**，读者可自行在大数据/GPU 环境复现。

## 二、总体技术路线

### 2.1 系统分层

```
┌─────────────────────────────────────────────────────────────────────┐
│                        在线问答层（RAG 主流程）                        │
│                                                                     │
│  Streamlit 界面 ──► NLU模块 ──► 对话管理 ──► 检索模块 ──► 生成模块     │
│   (app/)         (意图识别)   (槽位填充/   (BM25+图)   (Deepseek)     │
│                   实体抽取     反问/策略)                             │
└──────────────────────────────────┬──────────────────────────────────┘
                                   │ 读取
┌──────────────────────────────────┴──────────────────────────────────┐
│                         知识层（离线构建）                            │
│                                                                     │
│  模拟数据生成 ─► 自动标注 ─► 模型训练 ─► 知识融合 ─► 图存储抽象接口     │
│  (商品/订单/   (BIO/三元组/ (BiLSTM+CRF  (TF-IDF消歧、  (memory 实现， │
│   售后)         意图标签)     R-BERT、     规则统一、    预留 Neo4j)    │
│                              BERT意图)    同义词对齐)                 │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.2 数据流

**离线（一次性构建）：**
1. 模拟数据生成器产出商品表 / 订单表 / 售后规则表；
2. 自动标注器为文本打上 NER 的 BIO 标签、关系抽取的三元组标签、意图分类标签；
3. 训练三个模型：`BiLSTM+CRF`（NER）、`R-BERT`（关系抽取）、微调 `BERT`（意图识别）；
4. 用 NER + 关系抽取模型把原始文本转化为**三元组**（头实体、关系、尾实体）；
5. 知识融合（实体消歧、实体统一、关系对齐）后写入**图存储**；
6. 对商品/政策等文本建立 **BM25 倒排索引**。

**在线（每次提问）：**
1. 用户提问 → 意图识别（微调 BERT）判断问题类型；
2. 实体抽取（NER 模型 + 词典）提取品牌、订单号、商品等实体；
3. 对话管理：检查所需槽位是否齐全，不齐全则**反问**补全，齐全则进入下一步；
4. 检索：BM25 按文本相关性检索 + 图查询按实体/关系检索，合并得到候选知识；
5. 生成：把候选知识 + 用户问题拼成提示词，交给 Deepseek 生成最终回答。

### 2.3 技术栈清单

| 环节 | 技术/库 | 说明 |
|---|---|---|
| 编程环境 | Python 3.12（conda `python_ai` 环境） | 本机已确认 |
| 深度学习 | PyTorch 2.6（CPU）+ HuggingFace `transformers` | 预训练模型：`bert-base-chinese` |
| 分词 | `jieba` | 中文分词 |
| 检索 | 自实现 BM25 | 基于 jieba 分词后的词频统计 |
| 知识图谱 | `networkx`（内存）+ 抽象存储接口 | 生产方案为 Neo4j |
| 实体消歧 | `sklearn` 的 TfidfVectorizer + 余弦相似度 | 环境已装 |
| 大模型 | Deepseek 官方 API（OpenAI 兼容，`openai` 库调用） | 模型 `deepseek-chat` |
| 界面 | `streamlit` | 网页聊天 |
| 配置 | `.env`（python-dotenv） | API key 不写死在代码里 |

## 三、详细设计

> 每个模块按"职责 / 输入 / 输出 / 实现要点 / 生产化"五段式描述。

### 3.1 模块一：模拟数据生成与自动标注

- **职责**：生成贴近电商场景的模拟数据，并自动产出训练/评测所需标注，替代"数据部门提供数据"这一环节。
- **输入**：无（纯生成）。
- **输出**：
  - `data/raw/`：商品表、订单表、售后规则表（JSON/CSV）；
  - `data/annotated/`：NER 标注集（BIO 格式）、关系抽取标注集、意图分类标注集。
- **实现要点**：
  - 商品数据：品牌（耐克/阿迪达斯/华为/小米…）、类别（手机/鞋/包…）、型号、价格、颜色、库存、参数（如"支持5G"）；
  - 订单数据：订单号、用户、商品、订单状态（待付款/已发货/运输中/已签收/已退货）；
  - 售后规则：7 天无理由、退换货条件、运费政策；
  - **标注自动生成**：生成句子时同步记录实体起止位置与类型（如"耐克 Air Max 多少钱"→ 品牌[0:2]、商品型号[3:11]），保证"数据 + 答案"严格对应，评测才有标准答案。
- **生产化**：真实场景中由数据部门提供，本模块替换为数据导入 + 人工标注（Label Studio 等工具），标注规范一致。

### 3.2 模块二：命名实体识别（NER，BiLSTM + CRF）

- **职责**：从用户句子中识别出业务实体。
- **实体标签集合**（BIO 三标注体系：B=开始，I=内部，O=非实体）：

| 标签 | 含义 | 示例 |
|---|---|---|
| BRAND | 品牌 | 耐克 / nike |
| PRODUCT_MODEL | 商品型号 | Air Max / 小米15 |
| PRODUCT_CATEGORY | 商品类别 | 手机 / 跑鞋 |
| PRICE | 价格 | 599 元 |
| QUANTITY | 数量 | 两件 |
| ORDER_ID | 订单号 | 202608130001 |
| RECEIVER | 收货人 | 张三 |
| STATUS | 订单状态 | 已发货 |
| POLICY | 政策关键词 | 7 天无理由 |

- **模型结构**：`预训练词向量/BERT → BiLSTM 双向编码 → 全连接层 → CRF 解码`
  - BiLSTM 捕捉前后文依赖；
  - **CRF 层**负责解码时考虑标签之间的转移约束（如 `I-BRAND` 不能紧跟 `O`）。本项目**自实现 CRF**（`log-sum-exp` 计算归一化分数 + Viterbi 解码），不依赖外部库。
- **输入**：分词后的句子（BERT 版本则为字序列）。
- **输出**：每个 token 的标签序列。
- **训练**：交叉熵 + CRF 转移损失；快速模式下用数百条句子、数个 epoch，CPU 可跑。
- **生产化**：更大标注语料 + GPU 多 epoch + 早停，F1 目标 91.26%。

### 3.3 模块三：关系抽取（R-BERT）

- **职责**：给定句子和句子中的两个实体，判断它们之间的关系，产出三元组 `（头实体，关系，尾实体）`。
- **关系集合**：

| 关系 | 说明 | 示例三元组 |
|---|---|---|
| 生产品牌 | 商品 ← 品牌 | （Air Max，生产品牌，耐克） |
| 属于类别 | 商品 → 类别 | （小米15，属于类别，手机） |
| 价格为 | 商品 → 价格 | （小米15，价格为，2999元） |
| 库存为 | 商品 → 库存 | （小米15，库存为，200件） |
| 参数为 | 商品 → 参数 | （小米15，参数为，支持5G） |
| 订单包含 | 订单 → 商品 | （202608130001，订单包含，小米15） |
| 订单状态为 | 订单 → 状态 | （202608130001，订单状态为，已发货） |
| 适用政策 | 商品/订单 → 政策 | （已发货订单，适用政策，7天无理由） |

- **模型结构（R-BERT）**：`BERT + 实体标记(Entity Marker)`：
  1. 在头实体前插入 `[E1]`、头实体后 `[/E1]`，尾实体同理 `[E2][/E2]`；
  2. BERT 编码后，把头实体向量、尾实体向量、句向量拼接；
  3. 经过全连接层 + Softmax 得到关系类别概率。
- **输入**：句子 + 头尾实体位置；**输出**：关系类别。
- **生产化**：真实语料微调 `bert-base-chinese` 或 `chinese-roberta`，GPU 训练。

### 3.4 模块四：知识融合

- **职责**：消除冗余、统一表述，保证图谱中"一个实体一个节点"。
- **实现要点**（三个步骤，对应原方案）：
  1. **实体消歧（TF-IDF 相似度）**：用 `TfidfVectorizer` 把实体名转成向量，余弦相似度高于阈值（如 0.9）视为同一实体，合并；
  2. **实体统一（规则）**：维护别名映射表，如 `nike → 耐克`、`iphone15 → iPhone 15`；
  3. **关系对齐（同义词映射）**：`生产品牌 ↔ 品牌 ↔ 属于品牌` 归一到唯一关系名。
- **输出**：去重对齐后的三元组集合。

### 3.5 模块五：知识图谱存储（抽象层）

- **职责**：统一"读图谱"的接口，屏蔽底层实现。
- **设计**：
  ```
  GraphStore（抽象基类）
      ├── MemoryGraphStore（演示默认，基于 networkx）
      └── Neo4jGraphStore（生产预留，实现同接口，Cypher 语句写在文档）
  ```
- **核心接口**：
  - `get_entity(name)`：查实体节点；
  - `get_neighbors(entity, relation=None)`：查与某实体相连的关系与邻居；
  - `query_triples(subject, relation, object)`：按任意条件查三元组；
  - `add_triple/import_from_file`：写入。
- **生产化（Neo4j）**：给出对应 Cypher 示例（建节点、建关系、按关系查询），达到节点 31680 / 关系 82564 条规模。

### 3.6 模块六：NLU 与对话管理

- **意图识别（微调 BERT）**：
  - 意图集合：`查商品参数 / 查订单状态 / 咨询售后 / 查退换货政策 / 闲聊`；
  - 用 `bert-base-chinese` 接分类头，在自动标注的意图数据集上微调；
  - 快速模式下用少量数据几个 epoch，CPU 可跑。
- **实体抽取**：调用模块二的 NER 模型 + 词典匹配，提取槽位值。
- **对话管理（槽位填充 + 流程树 + 回答策略）**：

  ```
  意图 → 所需槽位 → 槽位是否齐全？
        ├─ 否 ──► 反问用户补全（多轮对话） ──► 回到意图解析
        └─ 是 ──► 选择回答策略
  ```

| 意图 | 所需槽位 | 回答策略 |
|---|---|---|
| 查商品参数 | 商品 | 图查询参数 → 生成 |
| 查订单状态 | 订单号 | 图查询状态 → 生成 |
| 咨询售后 | 商品/订单号 | 图查询政策 → 生成 |
| 查退换货政策 | （可选）商品类别 | 直接查政策模板 |
| 闲聊 | 无 | 模板回答，不查库 |

- **会话上下文**：维护 `session_state`，记录已填充槽位与历史，支持多轮追问。

### 3.7 模块七：检索模块（BM25 + 图检索）

- **BM25 检索**：对商品描述、政策文本等文档建**倒排索引**；用户问题分词后计算 BM25 分数，返回 Top-K 相关文档。BM25 公式：

  ```
  score(q, d) = Σ { IDF(w) · [tf(w,d)·(k1+1)] / [tf(w,d) + k1·(1-b+b·|d|/avgdl)] }
  IDF(w) = ln( (N - n_w + 0.5) / (n_w + 0.5) + 1 )
  ```
  参数：k1=1.5，b=0.75。本项目**自实现**该公式（约 50 行），便于学习理解。
- **图检索**：根据 NLU 提取的实体，沿图谱查询邻居关系（如"耐克"→"生产品牌"→ 所有商品；"订单号"→"订单状态为"→"已发货"）。
- **合并策略**：BM25 文本结果 + 图结构化结果**并集**，按相关性与实体命中率排序，供生成器使用。

### 3.8 模块八：生成模块（Deepseek）

- **职责**：把"检索到的知识 + 用户问题"联合建模，生成最终回答。
- **实现**：用 `openai` 库调用 Deepseek 的 OpenAI 兼容接口：
  - `base_url = https://api.deepseek.com`，`model = deepseek-chat`；
  - API key 从 `.env` 读取（`DEEPSEEK_API_KEY`），**不写死在代码**；
  - 提示词模板：

    ```
    你是电商客服助手。请仅根据以下"参考资料"回答用户问题，
    不要编造参考资料之外的信息。
    【参考资料】
    {检索到的三元组/文本}
    【用户问题】
    {question}
    ```
- **降级策略**：API 调用失败或未配置 key 时，降级为规则模板回答（直接从检索结果拼装），保证系统始终可用。

### 3.9 模块九：Streamlit 聊天界面

- **职责**：可视化人机问答，展示全过程（意图、实体、检索知识、生成答案）。
- **页面**：
  - 左侧：系统状态（模型是否就绪、API key 是否配置）；
  - 主区：聊天记录 + 输入框；
  - 展开区：每次回答附带的"意图 / 槽位 / 检索到的知识"调试信息。
- **交互**：多轮对话，会话状态保存在 `st.session_state`。

## 五、运行流程（脚本顺序）

1. `01_generate_data.py` —— 生成模拟数据与标注；
2. `02_train_ner.py` —— 训练 NER（BiLSTM+CRF）；
3. `03_train_relation.py` —— 训练关系抽取（R-BERT）；
4. `04_build_graph.py` —— 抽取三元组、知识融合、构建图与 BM25 索引；
5. `05_train_intent.py` —— 训练意图识别（微调 BERT）；
6. `06_evaluate.py` —— 评测：NER F1、关系抽取 F1、意图准确率、端到端满意度模拟；
7. `07_demo_cli.py` —— 命令行问答演示；
8. `streamlit run app/streamlit_app.py` —— 网页问答界面。
9. `run_all.py` —— 一键依次执行 1~6。

## 六、错误处理与降级策略

| 场景 | 处理方式 |
|---|---|
| Deepseek API 无 key / 超时 / 报错 | 降级为模板回答（直接拼装检索结果），界面提示 |
| 检索不到相关知识 | 明确告知"未找到相关信息"，并按意图给出建议话术 |
| 模型权重文件不存在 | 提示先运行对应训练脚本；`run_all` 会自动按序训练 |
| BERT 预训练模型首次下载失败（网络） | 给出手动下载路径与放置目录说明 |
| 槽位不全 | 对话管理反问补全，不进入检索 |

## 七、测试与评测方案

- **单元测试**（pytest）：
  - 数据生成正确性（标注起止位置与实体一致）；
  - 知识融合（`nike`→`耐克` 合并生效）；
  - BM25 排序（含关键词语句得分更高）；
  - 槽位填充（缺订单号时返回反问）。
- **评测脚本**（`06_evaluate.py`）：
  - NER F1（自实现精确率/召回率/F1，含 O 忽略）；
  - 关系抽取准确率；
  - 意图分类准确率；
  - 端到端：抽取 100 条测试问题，比较"系统答案"与"标准答案"（按检索命中 + 关键词覆盖打分，模拟人工满意度 93% 的统计口径）。

## 八、生产化方案（从演示到生产）

| 维度 | 演示版（本仓库） | 生产版（文档指导） |
|---|---|---|
| 数据 | 模拟 300~500 条 | 数据部门真实数据 + 人工标注，样本数以万计 |

| 部署 | Streamlit 本地 | API 服务（FastAPI）+ 前端 + 监控 |

## 九、风险与约束

1. **无 GPU**：所有深度学习训练在 CPU 上进行，只能小规模、快速模式；训练时间与数据量成正比，切勿在演示版上调大数据量。
2. **Deepseek API 依赖**：需要用户自行申请 API key 填入 `.env`；无 key 时系统以降级模式运行。
3. **BERT 预训练模型下载**：首次运行需联网下载约 400MB 的 `bert-base-chinese`。
4. **模拟数据的真实感有限**：演示版验证的是"流程与架构"，不代表真实业务指标。
5. **CLAUDE.md 约束**：全程使用中文注释与文档；不使用 git 提交。
